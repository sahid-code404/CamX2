# M8B — Computational DNG / Interchange Prototype

Status: Software narrow-direct CFA DNG reference checkpoint; standards/decoder/physical interoperability remains a separate evidence gate

M8B consumes a real M7 `FusedCfaRadiance` computational negative plus immutable accepted M5 calibration authority. It implements a bounded, deterministic, little-endian classic-TIFF DNG reference writer and a deliberately narrow bounded inspector. It does not use Android `DngCreator`, does not own Camera2, does not query current UI/topology, and does not change M7 pixels or product semantics.

## Implemented reference path

Production code lives in `core/imaging/interchange/`.

- `ComputationalCfaDngAuthority` requires an explicit bounded `UniqueCameraModel` string and the immutable `M5CalibrationProfile` that actually produced the M7 calibration digest.
- `ComputationalDngReservation` proves image, private uncertainty/provenance, metadata, strip-table, and total output bounds before writing.
- `ComputationalDngWriter` currently accepts only the real M7 `FusedCfaRadiance` path.
- The raster is written as uncompressed IEEE Float32 CFA data under DNG 1.4 compatibility semantics. M7 radiance is already black-subtracted, so the computational output black level is zero. A single output-derived white level is the ceiling of the maximum accepted CFA signal range. Uncensored M7 samples retain their Float32 values; censored values cannot exceed the declared output white boundary.
- The exported raster is the M7 active reference grid. `CFAPattern` is re-phased against that exported top-left rather than blindly copying the original sensor origin.
- A non-monochrome CFA export is rejected unless accepted color calibration exists. The M5 sensor-to-XYZ matrix is inverted to the DNG XYZ-to-camera `ColorMatrix` direction and encoded as bounded signed rationals. Missing metadata is never invented.
- One or two accepted illuminant/color-matrix entries are supported. The exact original M5 matrix values remain in private provenance even though TIFF SRATIONAL encoding is a bounded rational representation.
- `DNGPrivateData` begins with the self-identifying `CamX2\0` namespace and carries a deterministic canonical manifest plus per-pixel M7 radiometric variance, effective support, contributor count, censoring/reference-only state, and measurement-valid state.
- The private manifest retains M7 source hashes, included ordinals, calibration digest, M5/M6 evidence bindings, algorithm/graph/backend/determinism identity, build commit, output/manifest digests, uncertainty summary, exact source calibration values, and `learnedPriorChangedPixels=false`.
- `ComputationalDngInspector` validates bounded IFD counts, known TIFF field types, required DNG/CFA fields, offsets/extents, duplicate tags, private-data schema, strip continuity, declared raster extent, finite Float32 samples, color-matrix pairing, and the private uncertainty payload before allocating parsed arrays.

## Truth boundary

This writer is separate from `SensorDngWriter`. A computational DNG is not a sensor-negative file. Its pixel authority is the accepted M7 computational negative, not stale Camera2 metadata.

The current M7 product is CFA, so M8B implements only truthful CFA interchange. `LinearSceneRgb` is not generated by the accepted M7 reference and therefore no fake linear-DNG path is added here. When a genuine `LinearSceneRgb` product exists, its writer must use Linear DNG semantics with no CFA tags. RGB will never be remosaiced simply to make a Bayer-looking file.

M8B also does not emit a simple DNG `NoiseProfile` by guessing a mapping from M7 reconstruction uncertainty. The complete M7 uncertainty is preserved in the bounded private payload instead. A standardized uncertainty mapping can be added only after its semantics are proven.

## Reference file contract

The provisional reference writer uses:

- classic little-endian TIFF with 32-bit offsets and a hard 1 GiB implementation bound;
- one raw CFA IFD, no thumbnail and no chained IFD;
- `PhotometricInterpretation = 32803` (CFA);
- uncompressed Float32 samples with `SampleFormat = 3`;
- DNG/DNGBackwardVersion `1.4.0.0` for floating-point raw data;
- explicit orientation, CFA repeat/pattern/plane color/layout, zero output black level, output-derived white level, `UniqueCameraModel`, color matrix/illuminant, active area, and `DNGPrivateData`;
- deterministic 64-row strips with bounded strip count and 32-bit file offsets.

The narrow inspector is an acceptance tool for this reference writer, not a general-purpose hostile TIFF/DNG decoder.

## Security and resource bounds

M8B performs arithmetic with checked `Long` operations before layout/allocation. It caps image pixels, metadata reservation, private-manifest bytes, private-data bytes, IFD entries, strips, `UniqueCameraModel`, total output bytes, and classic-TIFF offsets. The writer streams private uncertainty and image samples to the caller output rather than materializing the full DNG in production memory.

The inspector rejects malformed/truncated offsets, duplicate tags, oversized counts, unknown TIFF field types, inconsistent strip tables, wrong DNG/CFA semantics, malformed private evidence, non-finite samples, and missing mandatory color authority.

## Validation

Unit tests cover deterministic byte-for-byte writing, parsed Float32 radiance/uncertainty round trip, CFA pattern and output level semantics, M7 provenance retention, censored/private flag preservation, missing color-calibration rejection, foreign calibration-digest rejection, bounded output admission, bounded `UniqueCameraModel`, duplicate tags, corrupted strip offsets, and truncated files.

CI success establishes only the software reference implementation. It does **not** yet certify Adobe Camera Raw, Lightroom, darktable, RawTherapee, libraw, platform gallery/editor behavior, or any exact physical camera profile. Those are independent M8B exit gates.

## Candidate decision

The narrow direct writer is selected as the **provisional M8B reference implementation**, not as a final irreversible shipping technology. A pinned/pruned DNG SDK or a standards-neutral computational master remains replaceable behind the frozen `ComputationalDngWriter` seam if security/interoperability evidence proves superior.

External decoder acceptance must compare named decoders against the same files and verify CFA phase, active area, color matrix interpretation, unclipped Float32 values, orientation, and preservation/recoverability of CamX2 provenance. Failure of a decoder candidate cannot mutate M7 negative truth.

## Tier-A review fields

**Invariant:** M8B reads immutable M7/M5 evidence only, never owns Camera2/ImageReader, never fabricates calibration, never renders, never demosaics/remosaics, and never relabels processed source data as computational RAW.

**Ownership transfer:** no Android image ownership enters M8B. Caller-owned `OutputStream` is written but not closed.

**Stale behavior:** the calibration-profile digest, CFA identity, and active-area geometry must match the immutable M7 product before writing begins.

**Failure classification:** DNG writer/parser/storage failure cannot mutate camera/profile support, calibration trust, active selection, or M7 reconstruction trust.

**CI guard impact:** `verify-m8b-interchange.sh` runs after M7 and before camera UI/native/build validation.

**Physical acceptance step:** run the exact generated files through a named external decoder matrix using real exact-profile M5/M7 evidence, then record structural validity, color/CFA interpretation, pixel-value behavior, metadata visibility, memory/runtime, and failure cases. Do not claim M8B interoperability certification until that matrix is green.
